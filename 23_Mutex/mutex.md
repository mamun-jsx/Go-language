# Mutex in Golang (মিউটেক্স)

Golang-এ `sync.Mutex` (Mutual Exclusion) ব্যবহার করা হয় যখন একাধিক Goroutine একই সাথে কোনো একটি শেয়ার করা ডেটা (shared resource) বা ভেরিয়েবল পরিবর্তন করতে চায়। 

যদি আমরা Mutex ব্যবহার না করি, তবে একাধিক Goroutine একসাথে একই ডেটা পরিবর্তন করার চেষ্টা করতে পারে, যা **Race Condition** (রেস কন্ডিশন) বা ডেটা ভুল হওয়ার সম্ভাবনা তৈরি করে। Mutex এই সমস্যা সমাধান করে একটি "লক" (Lock) মেকানিজমের মাধ্যমে।

### Mutex কিভাবে কাজ করে?
- **`mu.Lock()`**: যখন একটি Goroutine ডেটা পরিবর্তন করতে চায়, তখন সে প্রথমে এটি লক করে নেয়। এর ফলে অন্য কোনো Goroutine ওই ডেটা পরিবর্তন করতে পারে না; তাদেরকে অপেক্ষা করতে হয়।
- **`mu.Unlock()`**: কাজ শেষ হওয়ার পর Goroutine-টি লক খুলে দেয় (Unlock করে), যাতে অপেক্ষায় থাকা অন্য Goroutine-গুলো ডেটা ব্যবহার করতে পারে।

## Code Example (কোড উদাহরণ)

নিচে আপনার কোডটির একটি উদাহরণ দেওয়া হলো যেখানে ১০০টি Goroutine একসাথে একটি পোস্টের `views` (ভিউ) বাড়াতে চেষ্টা করছে। প্রতি লাইনের কাজ বাংলায় ব্যাখ্যা করা হয়েছে:

```go
package main

import (
	"fmt"
	"sync"
)

// post স্ট্রাকচার তৈরি করা হলো যেখানে views এবং একটি Mutex আছে
type post struct {
	views int
	mu    sync.Mutex // ডেটা লক করার জন্য মিউটেক্স ডিক্লেয়ার করা হলো
}

// inc ফাংশনটি views ১ করে বাড়াবে
func (p *post) inc(wg *sync.WaitGroup) {
	// defer ব্যবহার করে কাজ শেষে Unlock এবং Done করা হচ্ছে
	defer func() {
		p.mu.Unlock() // লক খুলে দেওয়া হলো (যাতে অপেক্ষায় থাকা অন্য Goroutine কাজ করতে পারে)
		wg.Done()     // WaitGroup-কে জানানো হলো যে এই Goroutine-এর কাজ শেষ
	}()
	
	p.mu.Lock() // views পরিবর্তন করার ঠিক আগে ডেটা লক করা হলো
	p.views++   // views ১ বাড়ানো হলো
}

func main() {
	var wg sync.WaitGroup
	myPost := post{views: 0} // পোস্টের প্রাথমিক views 0 সেট করা হলো

	// ১০০টি Goroutine একসাথে রান করানো হচ্ছে
	for i := 0; i < 100; i++ {
		wg.Add(1)            // প্রতিটি Goroutine-এর জন্য WaitGroup কাউন্টার ১ বাড়ানো হচ্ছে
		go myPost.inc(&wg)   // নতুন Goroutine চালু করা হলো
	}
	
	wg.Wait() // সব Goroutine শেষ না হওয়া পর্যন্ত মেইন প্রোগ্রাম এখানে অপেক্ষা করবে (ব্লক থাকবে)

	fmt.Println("number of views ", myPost.views) // চূড়ান্ত views প্রিন্ট করা হচ্ছে
}
```

## Use Case (ব্যবহারের ক্ষেত্র)
১. **Bank Account Balance Update**: যখন একসাথে একাধিক ট্রানজেকশন (টাকা জমা দেওয়া বা তোলা) একটি ব্যাংক অ্যাকাউন্টের ব্যালেন্স পরিবর্তন করতে চায়।
২. **View/Like Counters**: যেমন ওয়েবসাইটে কোনো পেজ ভিউ, ভিডিও ভিউ, বা লাইক কাউন্টার যেখানে একসাথে অনেক ইউজার ক্লিক করে।
৩. **Cache Update**: যখন একাধিক থ্রেড বা Goroutine একসাথে সিস্টেমে মেমোরি বা ক্যাশ (Cache) আপডেট বা ডিলিট করার চেষ্টা করে।

## Output (ফলাফল)
```text
number of views  100
```
**ফলাফলের ব্যাখ্যা:** 
লুপটি ১০০ বার চলার কারণে ১০০টি আলাদা Goroutine তৈরি হয়েছিল এবং প্রত্যেকে ১ বার করে `views` বাড়িয়েছে। `Mutex` ব্যবহার করার কারণে কোনো ডেটা লস বা ওভাররাইট হয়নি, তাই আমরা একদম সঠিক ফলাফল **100** পেয়েছি। 

**যদি `Mutex` ব্যবহার না করতাম কী হতো?** 
একাধিক Goroutine একই সাথে ভ্যালু আপডেট করার চেষ্টা করতো, ফলে অনেকগুলো আপডেট মেমোরিতে ওভাররাইট হয়ে হারিয়ে যেতো। তখন ১০০ এর বদলে ৯৫, ৯৮ বা অন্য যেকোনো ভুল ফলাফল আসতো।
